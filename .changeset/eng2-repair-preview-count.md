feat(b1/eng-2): add the typed `engine/repair-preview-count` op and move the repair preview's affected-set predicate engine-side. The repair preview's "which rows does this plan change?" question is value-defined, so the typed `overlay-row-count` op (which deliberately composes the effective union *without* the repair wrap — "values don't affect counts") cannot answer it; before this change the affected count was a **host-composed** SQL string executed through the generic `engine/query` op. The predicate now lives in `repair-preview-query.ts` as one exported pure function (`repairAffectedPredicate`, with `repairAffectedFilter` and `composeRepairPreviewCountSql`), producing the same two negated set-membership terms the host documented — term A `(t, v) NOT IN (VALUES (k, M[k]), …)` (a trim and a mapping can cancel: `trim = ' '` with `M = {a → ' a '}` maps a trimmed value straight back, so that row is not affected; without A a no-op plan could pass the zero-affected refusal) and term B `(t IN (keys) OR t <> v)`, after the NULL rule `IS NOT NULL` — so the composed SQL is **byte-identical** to the previous host composition (the host's transitional parity test and this package's real-engine conformance matrix both pin it). The new op is additive: one `count(*)` over the engine's composed export SELECT (the composed path that carries the repair wrap, so a column already repaired in the prefix is counted on its effective values), on the query lane per ADR 0040, one `{ affected }` safe-integer response, no second scan, and no cap, envelope, format or persisted-artifact change. The plan crosses the wire as **data, never SQL** (`{ column, trim?, pairs: [key, target][] }`): `parseEngineRepairPlan` checks the structure (a malformed plan is a typed malformed-envelope rejection), `assertEngineRepairPlanWithinEnvelope` refuses the plan's semantics pre-execution with value-free messages (empty plan, duplicate key, invalid trim, above the domain's 500-pair cap, and text no SQL literal can carry — a NUL is emitted raw by the literal escaper so DuckDB's lexer truncates it, and an unpaired surrogate has no lossless wire representation, both refused rather than handed to the engine), and the executor additionally refuses an unknown or non-textual column against its own folded effective schema (only `VARCHAR`/`TEXT`/`STRING` are repair targets — a repair's `trim()` re-declares the column type). Every refusal is pre-execution and value-free (ADR 0025): no key, target or trim value ever appears in a message. A count that is not a safe non-negative integer is refused instead of approximated. New client surface `repairPreviewCount(handle, overlay, plan)` validates the plan on the main thread first, so a hostile payload never crosses the boundary. `ENGINE_REQUEST_TYPES` gains one entry (23), the request/response types are exported, and the exported builder lets a host consume one definition of "affected" for both the count and its `overlay-range` examples so the two sets cannot diverge.
