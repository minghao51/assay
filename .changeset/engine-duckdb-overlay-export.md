feat(m4-2): overlay materialization + export/rewrite over the immutable base view (ADR 0012). New client surface (also the wire protocol and worker ops, all stateless — every request carries the overlay payload, the worker folds with `@assay/domain`'s `foldOverlay` and composes SQL as a pure function of (base view, ops), restart-safe by construction): `overlaySchema` (effective schema — post-rename names, post-cast DuckDB types, declared-cast validation), `overlayRowCount` (the domain's `liveRowCount`, optionally filtered with the m2-2 grammar over effective columns), `fetchOverlayRange` (edits visible, tombstoned base rows excluded, live inserts at anchored positions — the composed `assay_key` list key reproduces `effectiveRowIds` exactly, incl. dead-anchor degradation; optional logical row-id column `assay_row_id`, filters and sorts over the effective view with a deterministic `assay_key` tiebreak), and `exportView` (COPY-based materialization of the effective view to Parquet/JSONL/JSON/CSV + a streamed Arrow IPC path; deterministic per-format options; destination is a generated file under OPFS scratch `assay-exports/` (ADR 0017) — the source file is never written; the response carries path/rowCount/bytes so hosts can re-open and verify). **CSV exports are formula-injection-safe**: every column whose effective type classifies as the canonical string family — `VARCHAR`/`TEXT`/`STRING`/`CHAR(n)`/`BPCHAR`/`CHARACTER [VARYING]`/`ENUM(…)`, including via `column-cast` — and whose rendered text starts with `=`/`+`/`-`/`@` or contains TAB/CR is neutralized with the apostrophe-prefix convention, applied pre-export inside the composed SELECT; raw content stays visible in the other formats. **Engine type expressions are untrusted input** (`type-expr.ts`): base `columns[].type` and `column-cast.targetType` must be exactly one complete DuckDB type (typed `EngineTypeError` otherwise — statement separators, comments, unbalanced delimiters, trailing tokens rejected), enforced at the wire boundary, again in the composer, and fast-failed client-side with `EngineOperationError`; `text` values stay single-quote-escaped typed literals (backslashes are literal in DuckDB string literals; pinned). Lane policy per ADR 0040: overlay windows/counts/schema are grid-class (registry lane), export is a long user-initiated materialization (query lane). Cell values reach SQL only as typed literals; identifiers stay quoted; value-level cast failures surface as readable engine errors, never silent corruption.
