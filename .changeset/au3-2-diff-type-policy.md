fix(au3-2): compared-column type policy for the row-diff plan compiler. The compiler gated **key** columns with `keyTypesCompatible` but left shared non-key (change-compared) columns ungated, so a cross-family drift (e.g. `VARCHAR` on side A, `INTEGER` on side B) compiled `ok: true`; DuckDB then threw a value-bearing `Conversion Error` at execution. Every shared non-key column is now classified on both sides and refused with a new typed `shared-column-type-mismatch` binding error (message mirrors `key-type-mismatch`: both type spellings, both families, and the policy reason — value-free), attributed by `column` only (a shared column has no single offending side). The policy function is `keyTypesCompatible` reused verbatim, so same-family widening (`INTEGER` vs `BIGINT`) still compiles and JSON is refused on either side. Existing same-family golden SQL is byte-identical; only previously-`ok:true` incompatible pairs are now refused at compile time. Golden schema pair + regression pins, an exhaustive property pin that drifted compared columns never yield `ok: true`, and a real-DuckDB \(v1.5.5\) agreement leg (the refused comparison throws on the engine; the compiler now refuses it value-free) are included.
