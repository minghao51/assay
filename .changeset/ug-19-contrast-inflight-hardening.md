fix(web): contrast and in-flight feedback hardening (ug-19, findings UG-37/UG-15/UG-19).

**Empty-state contrast (UG-37).** The empty-state copy in the profile strip and top-k chart, the profile quantile tick labels and the SQL pane's empty-result status move off `--color-text-faint` / `--color-text-placeholder` to `--color-text-secondary`, the recorded `.filter-empty` precedent (7.14:1 on the subtle surface, AA in both schemes; the faint value measured only 4.29:1 there). No text size changes, no restyle, and the record dock's NULL _value_ marker keeps its de-emphasized token (it is a value, not empty-state copy). `tests/e2e/a11y.spec.ts` gains one driven zero-result scan per scheme: a compose-row filter that matches no row (grid at 0 rows) plus the SQL pane's empty-result state, scanned with the unchanged empty allowlist.

**Sort/filter in-flight signal (UG-19).** `App` owns the combined query epoch (`gridBusy: 'sorting' | 'filtering' | null`), the `FilterBar` reports its existing single-flight `pending` transition through a new optional `onPendingChange` prop, and `DataGrid` reports its own header-sort transition through a new optional `onSortBusyChange` prop. The grid renders `aria-busy="true"` on the `role="grid"` element and one polite, value-free footer status — `Sorting…` / `Filtering…` — while an epoch is in flight, cleared on settle for success AND failure; a second concurrent sort epoch keeps the signal until the last settles, `Filtering…` wins while both are in flight, and a new dataset clears both. The footer's Diagnostics disclosure, counters, edit/command errors and retry button are unchanged, and the read-only pipeline preview (no callbacks, no `queryBusy`) renders no busy UI.

**Loading-row edit gesture (UG-19).** `beginEdit` no longer returns silently when the row is still loading: it queues ONE pending gesture per grid (row, column, monotonic seq, plus the structural epoch captured at click time — the uxc-2 pending-gesture pattern) and opens the editor through the existing validated path once the model reports that slot `ready`. A slot that settles `error` drops the gesture with a visible, value-free notice (`That row could not be loaded, so the edit did not open.`) through the existing `grid-edit-error` + polite-region channel; a newer gesture replaces the older one, a dataset/schema/sort/filter/count change retires it instead of opening a different logical row, and ready-row editing plus the nested-column rejection are unchanged. Placeholder cells now carry the same double-click gesture (they previously had no handler at all). No FilterSpec/`GridViewportModel` protocol change, no engine change, no new dependency, no telemetry, no DOM reorder.
