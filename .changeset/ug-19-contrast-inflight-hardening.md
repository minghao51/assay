fix(web): contrast and in-flight feedback hardening (ug-19, findings UG-37/UG-15/UG-19).

**Empty-state and NULL contrast (UG-37).** The empty-state copy in the profile strip and top-k chart, the profile quantile tick labels and the SQL pane's empty-result status move off `--color-text-faint` / `--color-text-placeholder` to `--color-text-secondary`, the recorded `.filter-empty` precedent (7.14:1 on the subtle surface, AA in both schemes; the faint value measured only 4.29:1 there). The record dock's NULL _value_ marker and the grid's NULL marker now share the semantic `--color-null-text` token, whose light/dark values clear 4.5:1 on every surface a NULL can sit on, including the light row-hover background (5.37:1 / 7.70:1 on the subtle surface; the old placeholder colour measured 3.34:1 light). No text size changes and no restyle. `tests/e2e/a11y.spec.ts` gains one driven zero-result scan and one record-inspector NULL-marker scan per scheme, both with the unchanged empty allowlist, and a source pin verifies the token/rule layer directly.

**Sort/filter in-flight signal (UG-19).** `App` owns the combined query epoch (`gridBusy: 'sorting' | 'filtering' | null`), the `FilterBar` reports its existing single-flight `pending` transition through a new optional `onPendingChange` prop, and `DataGrid` reports its own header-sort transition through a new optional `onSortBusyChange` prop. The grid renders `aria-busy="true"` on the `role="grid"` element and one polite, value-free footer status — `Sorting…` / `Filtering…` — while an epoch is in flight, cleared on settle for success AND failure; a second concurrent sort epoch keeps the signal until the last settles, `Filtering…` wins while both are in flight, and a new dataset clears both. The footer's Diagnostics disclosure, counters, edit/command errors and retry button are unchanged, and the read-only pipeline preview (no callbacks, no `queryBusy`) renders no busy UI.

**Loading-row edit gesture (UG-19).** `beginEdit` no longer returns silently when the row is still loading: it queues ONE pending gesture per grid (row, column, monotonic seq, plus the structural epoch, overlay revision and any supplied logical row key captured at click time — the uxc-2 pending-gesture pattern) and opens the editor through the existing validated path once the model reports that slot `ready`. A slot that settles `error` drops the gesture with a visible, value-free notice (`That row could not be loaded, so the edit did not open.`) through the existing `grid-edit-error` + polite-region channel; a newer gesture replaces the older one, and a dataset/schema/sort/filter/count/overlay-revision change (or a mismatched captured key) retires it instead of opening a different logical row. Ready-row editing plus the nested-column rejection are unchanged. Placeholder cells now carry the same double-click gesture (they previously had no handler at all). No FilterSpec/`GridViewportModel` protocol change, no engine change, no new dependency, no telemetry, no DOM reorder.
