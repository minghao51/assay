feat(web): row identity made visible — sticky 1-based row-number gutter + record dock Prev/Next (ug-11, finding UG-12).

The grid now leads the header and every body row with a persistent row-number gutter: a fixed `2.75rem` leading track (header `columnheader` named "Row number" with a visible `#`; body `rowheader` cells, `data-testid="grid-row-number"`, `data-row-number`) carrying the **1-based** row number (`effective index + 1`). The cell is `position: sticky` at the left edge with an opaque, row-striped background and a separator border, so a horizontal pan never pulls the number away from the cells it labels (`aria-colcount` counts the extra leading column; row height, `aria-rowindex` and the virtualizer are unchanged). The record dock's visible title and aria-labels move to the **same** 1-based convention (`row N — full record`, `Record inspector — row N`, `Reloading record — row N`); `data-row-index` stays the 0-based effective index (the jump/scroll contract) and ug-12's `base #<ordinal>` jump announcements are untouched.

The record dock header gains `◀ Prev` / `▶ Next` (`record-prev` / `record-next`, accessible names "Previous row" / "Next row") that step to the **adjacent ready row**: rows whose slot is not `ready` (loading placeholder, failed span) are skipped rather than opened, and each control is disabled when no adjacent ready row exists in that direction. A step opens the row in the same dock through the existing request machinery (the App's `navigateToRow` seam, so the title/content re-read and the grid scroll-request are the ones every row jump already uses), never closes the dock, announces nothing (no new copy, no new shortcut), and keeps the existing Close/Escape/focus-restore behavior — the pressed step button is never remembered as the opener. Disabled step controls get a dimmed affordance rule. No telemetry, no engine/grid-protocol change, no DOM reorder, no value-bearing copy (ADR 0025).
