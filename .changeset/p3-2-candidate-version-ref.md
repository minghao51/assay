feat(p3-2): the pipeline runner now derives the candidate DatasetVersion reference (the D17-Q4 identity — logical id + schema fingerprint + provenance + materialization reference, no full content hash) from a completed/gated run's materialized output (`candidateVersionRefFromRun`). The Q4 quartet maps from runner data: the logical id and version id are host-owned (the version id defaults to a deterministic `<datasetId>@<fingerprint prefix>` — no wall-clock, D17-Q11); the schema fingerprint is SHA-256 over the canonical `name:type` rendering of the introspected relation's schema (algorithm recorded as `assay-schema-fingerprint-v1`; D19-OQ-6 free-string, stability fixture is p3-5's); the provenance carries the producing plan as `transformationRecipe` and the node's plan inputs as canonical `parentVersionIds`; the materialization reference is `{node}` for view/ephemeral/table outputs and `{export}` for export nodes (the runner's value-free `pipelineExportPath` OPFS path, ADR 0025). Every invalid request degrades to a typed located `PipelineRunRefusalError` — never a raw throw, never a silent fallback: unknown node, canceled run, unexecuted node, gate/source result, unreachable schema (dropped view; the raw engine error never crosses the seam), and unusable identity strings each carry their own reason. The publish boundary stays explicit: a publish-mode producing node refuses with the new `publish-materialization` reason (ADR 0033/0035) — publish is not wired for candidate derivation, and the failing-before-fix unit pin documents that wiring it would have to delete the pin. Seven additive `PipelineRunRefusalReason` members land with fixed value-free messages.
