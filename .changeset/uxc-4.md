fix(uxc-4): key the FilterBar auto-open on filter **identity** rather than the active count, with a user-collapse latch that is genuinely load-bearing. The auto-open effect previously fired only when `model.filters.length` changed, so a programmatic same-count replacement — the validation panel's "Show only failing rows" for rule B replacing rule A — silently swapped the predicate under a bar the user had collapsed. The effect now keys on an injective JSON serialization of the ordered `[column, predicate]` pairs (so delimiter-bearing column names or predicates cannot collide) **and** depends on the filter list itself, so a same-identity re-set re-fires it; the latch-match guard is then what preserves the user's collapse, rather than the dependency happening not to change. A different non-empty set (including a same-count replacement) re-opens and clears the latch; emptying the filters never force-opens and retires the latch, so a fresh filter after empty auto-opens as before. Collapsing mid-apply latches the **incoming** set rather than the pre-apply one on screen, so a user's own edit landing cannot force-open over their deliberate collapse. No engine/model/`FilterSpec` grammar change; six new component pins cover the replacement, the latch, the empty→filter path, the toggle, the empty-reset path, and the collapse-during-apply race.
