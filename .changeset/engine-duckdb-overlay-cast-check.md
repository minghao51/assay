feat(m4-4b): add an engine-side cast-conversion check so a host can validate-before-commit a `column-cast` (ADR 0012). New client surface `overlayCastCheck(handle, overlay, { column, targetType })` folds the **pre-cast** overlay state, strictly validates the target type (and rejects unknown effective columns) with the typed `EngineOperationError` before posting, then asks the worker whether any non-NULL value of the effective column cannot convert — a boolean only, never dataset values (ADR 0025). The check answers exactly what committing the cast would do: the domain collapses cast chains to a single direct `CAST(value AS final_type)` (`stepColumnCast`), so the composed SQL applies one `TRY_CAST(<raw value> AS <target>)` predicate per value source — the un-edited base column (ordinal-excluding edits and tombstones) and each raw edit/insert literal — unioned as an early-exit existence probe (`SELECT 1 … LIMIT 1`). No literal is hard-cast to the base column type before its own `TRY_CAST`, so a cross-type string edit on a numeric base (e.g. `price DOUBLE`, prior cast to VARCHAR, `cell-set 'hello'`, check `→TEXT`/`→INTEGER`) cannot throw where the commit succeeds. Edits, inserts, tombstones, renames and prior casts are respected via the shared `baseColumnEdits`/`insertColumnValue` value-expression helpers; NULLs never count as failures and all-NULL/empty inputs are `false`. The new `engine/overlay-cast-check` protocol request/result rides the query lane per ADR 0040 (a worst-case all-convertible `TRY_CAST` is a full-column scan, exactly the heavy query-class work that must never block grid windows), and a malformed recognised instance is answered with exactly one typed `engine/error`. `@assay/testing` gains the `overlay-cast-check` conformance scenario (all-convertible false; one bad value mid-dataset true — the case the m4-4 1-row probe missed; bad value only in an inserted row true; bad value after a rename true; all-NULL false; a prior cast A→B with a check B→C whose direct base→C cast fails true — the review's chain; a prior-cast-plus-edit case true; a prior cast whose intermediate value fails the target while the direct base cast succeeds false — the symmetric false positive; a no-prior-cast column unaffected by another column's prior cast false; invalid target spelling typed error; unknown column typed error), plus an **agreement battery** that asserts the check's boolean equals actually materializing the committed cast (reviewer's DOUBLE-base cross-type-edit repro → TEXT false / INTEGER true; numeric base + numeric edit + prior cast; DATE base with valid/invalid edits; insert-only bad and valid values with prior casts; tombstoned and expunged rows false; all-NULL; empty effective relation; a cast chain plus an edit) — CLI-1.5.5-derived expectations, and the subject surface to run it.
