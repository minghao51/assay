feat(ug-6): document-level Undo/Redo shortcuts plus a first-append History cue. One `window` `keydown` listener now maps Ctrl/Cmd+Z to the editing session's existing `handleUndo` and Ctrl/Cmd+Shift+Z (and Ctrl/Cmd+Y) to its existing `handleRedo` — shortcuts for the SINGLE visible Undo/Redo pair, never a second control pair (ux-3 ruling). The listener is active only in the ready phase, handles each event at most once, and `preventDefault()`s only a gesture it actually handled; events another handler already prevented are ignored. Native text undo is preserved: the new pure `lib/history-shortcut.ts` classifier returns `null` (no handling, no prevent) whenever the event target is an `input`, `textarea`, `select`, a `contenteditable` host, or a node inside one, so Ctrl+Z inside the cell editor, the SQL editor or a filter input keeps the browser's own text undo. The history surface cue is an auto-expand of the existing History section on the FIRST appended operation only (0 → >0 `entries.length`): undo/redo are cursor moves that never change the length, a dataset open/reset moves it down to 0, and the cue is one-shot, so collapsing History keeps it collapsed for later appends. `openSection('history')` is the existing disclosure seam — no new badge token, control, DOM reorder, telemetry or engine/overlay change; the ug-17 `History · N pending` summary is untouched. Pins: 11 unit rules for the classifier/cue transitions, 6 real-App component pins (ready undo/redo/preventDefault, non-ready inertness, editable-target pass-through, unmount cleanup, single-pair preservation, the 0 → >0-only cue across collapse/undo/redo/new dataset), and one real-Chromium e2e leg (edit auto-expands History, Control+Z reverts, Control+Shift+Z and Control+Y redo, one Undo/Redo pair only, and Ctrl+Z inside the open cell editor never moves the staged history).
