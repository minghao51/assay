feat(m3-2): nested grid cells render a bounded, depth-aware preview instead of raw `JSON.stringify`. New pure module `grid/nested-preview.ts` (`formatNestedPreview`): total (never throws — cycles, hostile getters, and exotic shapes map to marked text), deterministic (own-key order as delivered by Arrow, never re-sorted), length-capped (default 120 chars, honest `…` marker on every cut), and depth-aware (values at the depth cap elide, e.g. `{"a":{"b":{"c":…}}}` — the full value stays the inspector's job). NULL/`""`/`[]`/`{}` render distinctly; `NaN`/`∞`/`undefined` members are no longer lied about (JSON.stringify rendered them as `null`/dropped). Handles both plain JSON shapes and the raw Arrow cell shapes that reach the main thread (struct record-likes; list slices read positionally via `{length, get}`; epoch-ms timestamps per the m3-1 worker-boundary contract). Data cells deliberately carry no `title` attribute (no multi-KB tooltips; overflow stays CSS ellipsis). Grid e2e (`tests/e2e/nested-grid.spec.ts`) pins exact preview strings for the nested fixture's depth-3 struct, list-of-structs, empty/NULL lists, NULLs inside structures, the quoting-hostile key, and a unicode label — derived from the module's output and cross-checked against the DuckDB CLI.
