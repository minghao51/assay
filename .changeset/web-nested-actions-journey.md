feat(m3-5): one-click nested data actions + the M3 exit-criterion journey. The schema tree (m1-6) now offers **Flatten** on STRUCT column roots, **Explode** on LIST column roots, and **Extract path** on struct child fields (declined honestly through list elements — the tree carries no indices); every nested grid column header carries one typed action mirroring its type (STRUCT → Flatten, LIST → Explode). Both surfaces emit an intent that composes through the m3-4 pure composer (`nested-compose.ts`) against the parsed DESCRIBE types and the SQL-facing view name, then hands the SQL to the m2-4 editor/result pane, which shows the exact statement and runs it (composed requests supersede an in-flight run via the existing `RunGuard`). Composition failures surface as a readable `role="alert"` message — never a silent no-op. New `tests/e2e/nested-journey.spec.ts` walks the M3 exit criterion end to end on `fixtures/jsonl/nested.jsonl`: schema tree → bounded previews → full-depth record inspector → one-click flatten (`meta.src`/`meta.ver` pinned) → keyboard explode (`tags` × `tags.pos`, order-free pinned multiset incl. NULL/empty-list semantics) → path extraction (`deep.a.b.c` pinned), with the composed SQL asserted visible in the editor after every action.
