feat(m3-3): record inspector — a row-level panel showing the entire record as a JSON disclosure tree, at every depth (the full-value layer the grid's capped m3-2 previews deliberately are not). New pure module `record/record-tree.ts` (`buildRecordTree`): total (cycles → marked `(circular)` leaves; hostile getters/traps degrade to `(unreadable)` leaves per value, never throwing into the render path), deterministic (column order = schema order; struct key order as delivered, never re-sorted; positional list children), honest distinctions (NULL vs `""` vs `[]` vs `{}`; bigint as number-strings; epoch-ms timestamps as plain numbers per the m3-1 worker-boundary contract; binary as `<N bytes>`), with node summaries reused from `formatNestedPreview` (imported, not forked). `RecordInspector.tsx` renders the tree with the m1-6 disclosure pattern (native `aria-expanded` toggles, nested lists — text nodes only, never markup), plus expand-all/collapse-all. Rows open it via click or Enter; lifecycle + freshness live in Node-tested `record/record-state.ts`: the pinned policy is that an epoch shift (accepted sort/filter — row identity is positional in v1) closes the panel rather than silently swapping or stale-rendering the record, with a `RunGuard` token gate (reused from the SQL pane) guarding the render path. E2e (`tests/e2e/record-inspector.spec.ts`) pins full-depth values against the nested fixture, cross-checked with the DuckDB CLI.
