feat(ew-03i-a): carry CSV interpretation options on a typed closed vocabulary with a non-adopting preview op and a single-slot preview registry (EW-03I engine/protocol slice; ADR 0049; the acquisition probe's proven shapes).

**The closed vocabulary** (`csv-options.ts`, the single source of truth the web surface imports rather than duplicates): `header`, `delim` (alias `sep`), `quote`, `escape`, `columns`/`types` (declared map), `all_varchar`, `nullstr`, `dateformat`, `comment`, `skip` — plus `sample_size`, **preview-only** and refused on `engine/open`. Deferred keys (`strict_mode`, `null_padding`, `parallel`, `encoding`, `compression`, `max_line_size`, `buffer_size`, `decimal_separator`, `thousands`) and the refused-always keys (`ignore_errors`, `store_rejects`/`rejects_*`, `delimiter`/`separator`, `filename`, `union_by_name`, `hive_*`, `files_to_sniff`, `column_names`, `names`, `normalize_names`, `force_match`, `auto_detect`, `auto_type_candidates`, unknown keys) are refused with the key named — values never echoed. `parseCsvOptions` is the ONE total validator run twice (client before send; worker before any engine touch — the main thread is untrusted); every declared type value passes `validateEngineTypeExpression` in both passes.

**Composition** reuses only `quotedIdentifier`/`sqlStringLiteral` plus the closed option names over engine-generated file names: option string values are literal-quoted (a hostile `delim` stays inside its literal), map literals quote keys AND values, canonical argument order is deterministic, the bare scan composes byte-identically to the quick-open `read_csv('tN')`, and `sniff_csv`'s `Prompt` is transported as display text and never executed. The sniff receives every option except the declared-columns map (declarations are not inference inputs); `sample_size` rides the sniff and the preview scan but never `engine/open`.

**Protocol**: `engine/csv-preview` (non-adopting review) plus an optional `options` field on `engine/open` (adoption of an already-reviewed set). The preview response carries the sniff payload (delimiter/quote/escape/newline/comment/skip/header/per-column types/dateformat/Prompt), the effective option set actually composed, and a bounded sample with its cap STATED — never a validation verdict. No cancel, release, sniff-only op, or raw DDL escape hatch is added; quick open without options keeps its byte-identical SQL.

**Preview workload budget** (ADR 0049 acceptance resolution 8): `sample_size` is bounded to the inference budget (100,000 rows — half the EW-03D §6.3 measured 200k-row corner, ≈5× DuckDB's own 20480 default); `sample_size = -1` (read every row) is refused, never silently capped; over-budget requests are refused before registration or any SQL.

**Known carry-risk (recorded per review round 2, owned by the orchestrator for EW-03I-b):** the 100,000-row inference budget bounds ROWS, not bytes-per-row, wasm-heap pressure, or elapsed time — a wide-row or large-byte candidate inside the row budget can still stress the engine. The budget policy stays as shipped; the bytes/heap/elapsed bound is the EW-03I-b risk to carry.

**Open/preview race discipline**: the preview slot intent and its supersede generation are taken synchronously before the preview op's first await, so an `engine/open` dispatched after a preview always invalidates it — a registration completing after that open self-releases (view-then-file, best-effort), never installs as the live slot, and the late result payload is discarded in favour of exactly one typed supersession reply. Open and dispose supersede via the same synchronous path; the pre-result checkpoint makes a stale delivery impossible.

**The single-slot `PreviewRegistry`** (in the executor, never `TableRegistry`): own id sequence `p1…`, view name `assay_preview_pN`, file name `preview_pN`; acquisition via `registerFileHandle` on the candidate `File` — bare registration, no view (the probe proved scans need none). Re-stage drops the previous slot first (view-then-file, both swallowed — a failed `DROP VIEW` still reaches the `dropFile`); any `engine/open` and `engine/dispose` release the slot best-effort too; a failed stage still tracks its name so nothing escapes the slot's own lifecycle (the "+1 until the next slot event or dispose" accounting row). The preview never reads its candidate's bytes back (`copyFileToBuffer` would poison the release into a 1-byte stub). Preview work sits on the query lane (ADR 0049 resolution 8).

**Failure surface**: refusals are typed and value-free with the offending option KEY named; engine-touching failures propagate the engine's own message (the honest EH first line where available, ADR 0048) and are never classified from glue text.

**Fixtures** (`fixtures/csv/`): six golden synthetic CSVs (leading zeros, quoted empty, late bad row beyond a small sniffer sample, semicolon dialect, unsafe integers beyond 2^53, duplicate/empty headers) with a deterministic generator and a SHA-256 `manifest.json`, verified bidirectionally by the package tests. CLI-control agreement tests compose the scan/sniff/sample SQL against a real DuckDB when the pinned CLI is present — comparison only (ADR 0049 item 8: the browser build stays the only capability truth).

No telemetry, no dependency, no format-detection change; the web preview panel is the successor row (EW-03I-b).
