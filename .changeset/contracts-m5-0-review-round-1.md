fix(m5-0): reviewer round 1 — rule numbers are now **exact or rejected**: a written number the YAML parse would silently alter (e.g. `min: 9007199254740993`, which reads back as `…992`) fails with a new typed `imprecise-number` error naming both values, instead of corrupting the contract (the vocabulary includes `BIGINT`/`HUGEINT`, so precision honesty matters); `contractTypeHint` and misplaced-key hints use own-property lookups, so adversarial spellings/keys like `type: __proto__` or a `toString:` key produce honest typed errors instead of inherited-member garbage (the latter previously could crash the error builder, breaking the never-throws promise); rule-less `columns[]` entries (only a `name`) now normalize away like the other semantically-empty rules — one shape per meaning, nothing for the m5-1 compiler to second-guess — while still participating in duplicate-name rejection; BOM-prefixed documents report error columns as the editor shows them (the invisible BOM is no longer counted on line 1); `ColumnRuleSet.type` is typed as `ContractTypeSpelling` (closed vocabulary, compile-time enforced), and the `unique: false` doc typo is fixed. No input-size/nesting limit is enforced by the parser, deliberately — documented as a caller-side concern.
