fix(rd-3c): make the durable edit error reachable from every task again. Since rd-3b hides the inactive tasks' sections, an engine rejection, cast refusal or non-applied op — whose message lives in the Editing section (Change) — was invisible to a sighted user editing a typed or temporal cell from Explore: the value silently reverted. When the durable `editError` transitions to a non-null value the shell now reveals the Editing section through the existing `revealSectionFromNav` seam (activate Change, expand, and scroll the section into view through a new opt-in `{ scroll: true }` option — a programmatic reveal gets no anchor scroll of its own) **once per error**, without moving focus, and skips the reveal when Change is already active with Editing already open. A ref of the last revealed error resets when the error clears, so returning to Explore while the error persists is not undone and a later error reveals again. Nothing else changes: no new durable or session state, no new test id, message or second render of the text, no `useEditingSession`/grid change, and no telemetry. The only new state is the transient app-local `{ id, seq }` scroll request that sequences the render-then-scroll effect (the seam's other callers omit the option and are behaviourally unchanged) — `grid-edit-error` and the single polite live region are untouched. Pinned from the Explore default in `App.column-ops.test.tsx` (reveal, success/no-op negative controls, ref guard, re-reveal after clearing) and in `grid-editing.spec.ts` (automatic reveal + focus not moved into the pane + the positive controls).
