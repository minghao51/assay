fix(web): repair theme completeness for the two telemetry surfaces (uxv-1 / R-09). `.telemetry-settings-dialog` and `.telemetry-disclosure` painted `background: var(--color-surface-panel, #fff)`, but `--color-surface-panel` is declared nowhere in the token layer, so the hard-coded `#fff` fallback won in _both_ schemes: the Settings dialog and the first-run telemetry disclosure rendered as white panels in dark mode, with light-scheme body text on them measuring 1.21:1. Both surfaces now use `--color-surface-elevated` — the scheme-aware token the export dialog already uses, declared in both scheme blocks, and the right semantic choice here because these are floating `role="dialog"` panels (the page surface `--color-surface` would merge them into the body in both schemes) — and the colour fallback is removed entirely, so a future token typo resolves to nothing and fails the contrast evidence visibly instead of silently painting the panel white. No new token name, no new dependency, and no behaviour change: consent copy, preference semantics, storage keys, event payloads and the opt-out path are untouched.

Evidence is browser-measured in Chromium, both schemes, normal text against its actual computed background (AA floor 4.5:1): Settings dialog panel text 16.95:1 light / 13.43:1 dark (native Close control 18.26:1 / 5.33:1 on its own UA face); the configured-build disclosure copy 16.95:1 light / 13.43:1 dark with both consent actions at 5.33:1 dark, axe green under the unchanged empty allowlist, and every collector request aborted (`0` delivered). The configured leg is a new isolated `tests/visual/telemetry-disclosure-theme.spec.ts` + `playwright.telemetry.config.ts` (outside the stock `tests/e2e` testDir in both directions) that registers a context route aborting `https://collector.example.invalid/**` before navigation, blocks service workers and clears local storage, so the real disclosure is exercised without sending metadata. New pins: a driven both-scheme Settings contrast + token-identity check in `tests/e2e/theme.spec.ts`, both-scheme Settings axe scans in `tests/e2e/a11y.spec.ts`, and a source-level `apps/web/src/telemetry/telemetry-surfaces.theme.test.ts` that fails on any colour fallback or undefined surface token.
