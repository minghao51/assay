feat(ux-4): type-aware filter builder + collapsible filter bar. The filter surface is now a collapsed-by-default disclosure whose summary reports the active count from the grid model (`Filters · 2 active`, bare `Filters` at zero). Expanding it reveals a per-column operator/value builder — numeric comparisons (`= ≠ > ≥ < ≤`), string equality/inequality/`contains`, temporal comparisons with typed date/timestamp literals, boolean `= true`/`= false`, and `is null`/`is not null` for every kind — that compiles to the existing `FilterSpec` predicate grammar, so the engine contract, the engine, and `GridViewportModel` are unchanged. Values remain untrusted text: string values are single-quoted with `''` escaping, `contains` becomes a `LIKE` with `%`/`_`/`\` escaped, and invalid combinations (empty value, non-numeric input on a numeric column, malformed date) are rejected client-side with inline copy before any engine round-trip. The per-column SQL-fragment escape hatch is preserved for power users, and the validation panel's programmatic "Show only failing rows" filters now auto-open the bar while the chips remain mirrored from the model. New pure module `filter-builder.ts` is unit-tested for classification, catalogs, and compilation; a new non-SQL e2e journey covers the builder path. This is a **minor** bump because it adds a new user-facing capability (the builder and the collapsible bar) without removing or changing any existing contract.
