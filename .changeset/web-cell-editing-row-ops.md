feat(m4-3): real cell editing, row ops, dirty state, and undo/redo over the edit overlay (ADR 0011/0012). The ready phase now owns an editing session — the immutable `OverlayBase` (a stable function of the file version) plus a `TransformationHistory`; every edit is a typed `EditOp` appended through the domain fold, undo/redo move the history cursor, and the grid re-materializes through a fresh data epoch (the base is never mutated). The provider composes over the engine's overlay surface (`overlaySchema`/`overlayRowCount`/`fetchOverlayRange` with `includeRowIds`), keeping a fast base path while the overlay and query state are empty; the engine-facing op list is projected from the folded state so it composes correctly (see `edit/overlay-projection.ts`). The grid gains Enter/double-click inline editing with typed input constraints derived from the parsed DuckDB type (`BIGINT`/`DECIMAL` stay engine-parseable text, booleans offer true/false, temporal/text defer to the engine), a distinct NULL affordance and rendering (NULL is never an empty string), readable `role="alert"` rejections that leave state unchanged, dirty markers (`data-dirty`) distinct from NULL and clean state, insert-row/delete-row affordances, and undo/redo controls with honest cursor-end disabled states. The record inspector's freshness policy is extended for the editing era: a query/schema shift closes it, an overlay value change re-reads the same logical row (rendering a stale-pending state while the refetch is in flight — the old snapshot never renders as current). Tests: typed-input constraints, history/engine projection, provider overlay composition, inspector freshness, and e2e journeys (edit→visibility→undo→clean, readable rejections, insert/delete, rapid epoch changes with no stale window).
