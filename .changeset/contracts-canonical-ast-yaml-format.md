feat(m5-0): add the native contract format — canonical Contract AST + YAML, the foundation the whole M5 validation track compiles from (ADR 0013/0026). New pure `@assay/contracts` surface: the typed **`ContractV1` AST** (metadata `name`/`version`/`description`; per-column rules — declared-type expectation, `required`, `unique`, `min`/`max`, `allowed-values`, `regex`, `max-null-share`, `min-distinct-share`; dataset row-count bounds) with canonical normalization (false booleans, empty descriptions and rule-less `dataset` mappings normalize away; an empty `allowed-values: []` is kept — it is a real constraint); a **total YAML parser** (`parseContract`) that never throws — malformed documents come back as typed `ContractError[]` (`yaml-syntax`, `unsupported-format`, `missing-key`, `unknown-key`, `wrong-type`, `out-of-range`, `duplicate-key`, `unknown-type`), each with a 1-based line/column and an actionable message (misplaced keys say where they belong; alias spellings like `TEXT` suggest the canonical spelling); the **canonical serializer** (`serializeContract`) with fixed key order, flow `allowed-values`, no folding, byte-stable output — parse∘serialize round-trips and is canonically stable regardless of source key order/whitespace (seeded property suites + 2 500-case fuzz totality); and the **documented in-package type vocabulary** (`CONTRACT_TYPE_VOCABULARY`, 21 canonical scalar spellings) that the m5-2 engine agreement test will pin against. Honesty bar enforced: unknown/misplaced YAML keys, duplicate rules and duplicate column names are typed errors, never silently dropped; regex patterns are carried verbatim (RE2 dialect validation is m5-1's binding concern); the lint-enforced purity boundary keeps the package free of React, browser APIs, and other `@assay/*` imports. Adds the single runtime dependency `yaml` (MIT, compatible with AGPL-3.0-or-later).
