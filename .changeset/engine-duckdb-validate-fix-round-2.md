fix(m5-2): round-2 re-review — three critical fixes, two warnings. **(1) Comments no longer bypass the SQL gate**: the plan scanner is now fully SQL-aware — a single lexical pass tracks line/block comments, single-quoted strings (`''` doubling), double-quoted identifiers (`""` doubling), and the dialect string forms the compiler never emits (dollar-quoted `$$…$$`, `E'…'` escape strings), and **comment-bearing SQL is refused outright** (typed error, zero SQL): a commented pseudo-reference (`SELECT … /* FROM "relation" AS "src" */`, the reviewer's exact browser probe) can no longer satisfy the compiler-shape occurrence counter, and occurrences hidden inside string literals never count either. **(2) `sampleLimit` is CLAMPED, not refused** (orchestrator adjudication, supersedes the round-2 rejection): every safe integer K ≥ 1 parses at the wire and the executor runs each rule query as `SELECT * FROM (<exact rule SQL>) LIMIT min(K, 100)` — the inner SQL stays byte-identical, the outer LIMIT bounds only the rows RETURNED (a huge-K plan cannot request unbounded row return), and the inner `count(*) OVER ()` still reports the rule's FULL violation count on every returned row, so `sampleFailures ≤ min(K, hard max)` holds literally and `failCount` is never corrupted by the clamp (documented materialization semantics: the window scan is inherent to `failCount` and not bounded by the clamp — the clamp bounds returned rows). K < 1 remains refused. **(3) Malformed plans and malformed responses can no longer hang the client**: a shape-valid plan whose counts exceed the dataset (the reviewer's two-row probe: `failCount` 3 over 2 rows) is failed by a new executor result-sanity guard with ONE typed `engine/error` (never an out-of-contract `failPercent > 100` response); the protocol parser additionally rejects `failCount > rowCount` payloads as malformed; and the client now REJECTS the pending promise with a typed `EngineProtocolError` whenever a worker response fails shape validation while claiming a pending `requestId` — no op (validate or otherwise) can hang forever on a discarded response, and follow-up queries keep working. **(W1) `ruleId` is pinned to the m5-0 rule-id grammar** (the compiler's error-path spelling `columns[<index>].<rule>` / `dataset.<rule>`), so engine failure-class messages can only ever interpolate compiler-shaped ids, never arbitrary plan content. **(W2) Containment cleanup completes BEFORE the success response is posted** (DROP when owned + ROLLBACK, both steps always attempted in order — a failed drop no longer skips the rollback), a cleanup failure surfaces as its own typed privacy-safe error instead of being swallowed, and the row-key-failure rollback-order pin is in place. The conformance suite pins all of it (clamped-K execution with full failCount, comment probes, the counts-exceed-dataset probe — 11 hostile probes now) and the Node fake subject mirrors the new boundary (grammar, comment refusal, clamp).
