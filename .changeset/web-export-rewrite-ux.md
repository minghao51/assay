feat(m4-5): the export/rewrite UX over the merged m4-2 export op — pick a format, write a **new file** from the current edited view, and re-open it. The dialog (`export/ExportDialog.tsx`) offers the engine's five formats (Parquet/CSV/JSONL/JSON/Arrow IPC) and states honestly that the engine applies fixed, deterministic options (there are no user-adjustable options in this version). Copy-vs-rewrite is unambiguous (ADR 0012): the notice says it writes a **new file**, that the opened file **is not changed**, and the wording contains no "overwrite"/"in place" language; the current-edited-view row count shown is engine-backed. Result feedback uses the engine's returned `{ format, rowCount, bytes }` verbatim (format + rows + size), and every failure path — engine rejection, OPFS read/write, a save picker that errors rather than being dismissed — surfaces as readable text stating that the opened file is unchanged, leaving the app usable. Destination follows the established picker patterns (mirroring `@assay/data-sources`'s capability vocabulary, implemented in `apps/web`): `showSaveFilePicker` when available (acquired **before** the engine export so the picker stays inside the click's user activation, then written with the OPFS-scratch bytes), otherwise a hidden-anchor download of those same bytes; dismissing the picker is reported as a cancellation with no engine work attempted. `export/scratch.ts` reads the engine's OPFS scratch path (`assay-exports/…`) through `navigator.storage.getDirectory()` (ADR 0017), so the source is never involved. The re-open journey is the normal open flow: the e2e captures the fallback download and reopens it via the filechooser, asserting the edited content returns. **Carry-over closed (m4-4):** decimal leaves nested inside structs/lists no longer render `<16 bytes>` — the parsed type tree from `parseDuckDbType` is threaded through the nested preview (`decimalSpecForParsedType`/`formatDecimalForParsedType`, `nested-preview.ts` `columnType` option), so `payload.geo.lat DECIMAL(21,1)` and `DECIMAL(p,s)[]` elements decode exactly, while a type-unknown or non-decimal 16-byte view keeps its honest binary summary. Tests: pure message/byte-formatting pins (incl. "never implies in-place"), capability detection + picker cancel/error + OPFS-read + write/download flows, an OPFS path navigator, a happy-dom dialog state-machine suite (format selection, cancel, failure, numeric feedback, wording), a nested-decimal decode suite, and e2e: export CSV + JSONL from an edited overlay (formula-injection bait `=SUM(A1:A2)` apostrophe-prefixed in CSV, raw in JSONL), re-open the exported JSONL showing the edited cell + inserted row, source-fixture byte-identity under export, dismissed-picker cancellation, and the nested-decimal render (mutants killed for overlay-dropped export, format pass-through, type-threading, and copy wording).

**Fix round (review):** three honesty/data-safety corrections, all in `apps/web` (engine surface untouched): (1) **same-source guard** — the save picker can return the opened source's own entry, and a direct handle write then replaced the source (observed: a 682-byte Parquet source became 144 bytes of CSV while the UI claimed the source was unchanged). The open flow now retains the picked source's identity (`App` captures the FSA handle via its own `showOpenFilePicker` wrapper, falling back to a name+size+lastModified suspicion for hidden-input sources, where no web API proves entry identity); `requestSaveDestination` threads it and resolves a new `refused-source` outcome **before any engine work or byte write** when the destination is (or may be) the opened entry — authoritative `FileSystemHandle.isSameEntry` for FSA opens, fail-closed on doubt; the dialog renders "That is the opened file — writing the copy there would change the source…" and stays usable. (2) **Count/copy honesty** — the dialog echoed the grid's filtered row count while `exportView` exports the complete, unfiltered, naturally ordered edited dataset; it now shows the domain's effective `liveRowCount` at the history cursor, states "complete edited dataset … natural order … Grid filters and sorting are not applied", and, when a filter/sort is active, adds an explicit "the copy ignores the view's filters and sorting and contains every row" note. (3) **Arrow guidance/MIME** — the success hint told users to re-open every format, but the engine rejects `.arrow` on open; the hint now appears only for parquet/csv/jsonl/json, arrow is described as "an interchange format for other tools; Assay opens .parquet, .csv, .jsonl and .json files", and the advertised MIME is corrected from the Arrow _file_ container to the IPC **stream** type `application/vnd.apache.arrow.stream` (the engine's `tableToIPC` default writer). Pinned by unit tests (same-entry refusal matrix incl. fail-closed, complete-dataset copy + active-filter note, per-format re-open guidance, stream MIME), and e2e (fake same-entry picker: refusal shown, no engine work, fixture byte-identical; filter active: dialog shows 5 not the grid's 3 and the JSONL copy holds all 5 rows; arrow: honest hint + first bytes `FF FF FF FF`, not `ARROW1`).
