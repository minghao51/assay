feat(m6-2): add the row-diff execution surface — `stageComparison(source)` + `diff(handle, comparison, plan, overlay?)` (ADR 0040 query lane). `stageComparison` registers a comparison dataset file into a single-slot OPFS-scratch view (never the source path, ADR 0017; re-staging replaces the previous slot so nothing leaks) and returns an opaque comparison handle carrying the staged view's DESCRIBE schema. `diff` executes a compiled m6-1 `RowDiffPlan` **byte-identically** with side A bound to the table's effective view (the m4-2 composed base + overlay relation, or the plain base view when absent) and side B bound to the staged comparison: the executor materializes both binding views under the plan's own relation names (side A through the m5-2 composed-view helper, whose baked `assay_overlay_ord` is the A-side row-key channel; side B as a thin pass-through), runs the three aspect queries plus the totals query inside a `BEGIN…ROLLBACK` containment transaction (always rolled back; only op-created views are dropped, and only when this op created them — a failed create never destroys a pre-existing user view), and resolves every sampled A-side ordinal to a grid-resolvable logical row key (`base:<anchor>#<ordinal>`, the m4-3 grammar; loud typed failure on an unresolvable ordinal). B-side samples are the documented report-only `b:<ordinal>` form (checkpoint C3). Samples are bounded by `min(plan K, hard max 100)` via an outer clamp that leaves the inner SQL and its window count untouched; the reported per-aspect counts must agree exactly with the totals query (the m6-1 no-divergence invariant asserted, not assumed) and must fit their documented result-sanity bounds — a corruption/foreign-signal net, not a semantics claim: keys may be non-unique and NULL keys group (the m6-1 contract), so `added ≤ rowCount(B)`, `removed ≤ rowCount(A)`, and `changed ≤ rowCount(A) × rowCount(B)` (compared without overflowing the safe-integer range). A count past its bound is one typed error, never an out-of-contract result; the totals agreement is the independent net for a count inflated while still inside a bound. Samples are presented in ascending ordinal order with a stable sort so the reported set is engine-version-independent (DuckDB's anti-join output order is not guaranteed; the plan SQL is untouched); duplicate A-side ordinals in the changed sample set are legal and inherent to non-unique / grouped-NULL keys (one pair per A×B row), and changed samples are a set of pairs, not distinct A rows. The reserved-result-column gate is symmetric across all three aspect queries, so a gutted `removed`/`changed` query fails the static gate rather than a shape error mid-op. A failed re-stage leaves no staged comparison — the previous slot is cleared before the new reservation, so it does not roll back to the prior slot. **Wire hardening (m5-2 precedent)**: a structural engine-side parser mirrors the m6-1 `RowDiffPlan` (discriminator/version, bounded NUL-free relations/keys with case-insensitive de-duplication, safe K ≥ 1), a malformed recognised `engine/diff`/`engine/diff-stage` request gets exactly one typed `engine/error` before any SQL, and beyond shape the executor refuses shadowed relations, comment-bearing or multi-statement SQL, string-masked pseudo-references, and non-compiler FROM shapes — requiring BOTH relations in the compiler's exact `FROM "<rel>" AS "a"`/`"b"` renderings and a three-arm totals `UNION ALL`. Engine errors are mapped to fixed, value-free failure classes; row keys and changed-column names are report content only (ADR 0025). The pure staging/diff machinery is also re-exported from `./node` for the m6-3 CLI.
