feat(d3-1): disclose the per-file header **rename list** in the CSV review, before adoption

EW-03D §8 D3 asks for DuckDB's auto-renames **plus the rename list** before adoption, and
EW-03I-b could only disclose the rule. This row derives the list, verifies it, and shows it
only when it can be trusted — a wrong list would name a column wrongly, so the bar is
exactness, never best effort.

**Where the list comes from.** The engine has no op that reports the raw header row, so
`apps/web/src/csv/header-renames.ts` reads a bounded head of the picked file
(`file.slice(0, 64 KiB).text()` — a documented constant, never `file.text()` on the whole
file), scans **exactly one record** with the **sniffed** delimiter, quote, escape and
terminator, reconstructs the names the reader will give those fields, and then **requires
exact equality** with `sniff.columns[].name` (count, text and order included).

**The rule is encoded from evidence, not assumption.** Verified against the installed
DuckDB v1.5.5 CLI and, in the browser, against the shipped build (the e2e legs on
`dup-header.csv` and the new `quoted-newline.csv` are the browser proof): an empty name
becomes `column{i}` with a **zero-based** position (`,a,b` ⇒ `column0`, not `column1` — the
behaviour sentence's illustration was the second-column case); a repeated name takes `_{n}`
from a per-base counter that is **case-insensitive** and shared across spellings
(`id,id,ID,ID` ⇒ `id`, `id_1`, `ID_2`, `ID_3`); a suffixed candidate that is already taken is
deduplicated again recursively (`a,a_1,a` ⇒ `a_1_1`); and each name is trimmed of ASCII
blank first. The scanner also had to decode what `sniff_csv` actually reports: unset
`Quote`/`Escape` arrive as the literal seven characters `(empty)` and `NewLineDelimiter` as
escape text (`\n`, `\r\n`), while `Delimiter` arrives as a real character.

**Show or fall back — never a partial list.** The pairs (`original → renamed`) replace the
behaviour sentence when the comparison passes, with an empty-name original rendered as
`(empty name)` and a verified file with nothing to rename saying so. Every other outcome
falls back to the existing behaviour sentence plus one honest limit sentence ("No per-file
rename list is shown for this file: it could not be derived safely from the head of the
file.") — no header row (`header=false`), the reader skipping rows before the header, a
user-declared `columns` map (which replaces the reader's naming, so a reader rename list
would be misleading), an unreadable file, no complete record inside the window, an
unterminated quote, an escape on the window edge, a shape the scanner will not interpret
confidently, a field count or a name that disagrees with the engine. The limit is stated as
ours; the engine is never implied to have failed.

**New fixture.** `fixtures/csv/quoted-newline.csv` has a header record carrying a quoted
delimiter and a quoted newline plus a duplicate and an empty name — the shapes a naive
`split(delim)` on the head gets wrong. It is generated by `fixtures/csv/generate.mjs` and
listed in the regenerated `fixtures/csv/manifest.json` (the engine package pins
manifest↔disk bidirectionally).

**Privacy, and nothing else moved.** Header names are file content: they are rendered as
text (no `innerHTML`, no `data-*` attribute, no log, no error string, no telemetry), and the
picked file's name is never read here at all (ADR 0025). No new telemetry, no dependency,
no protocol or engine change. Quick open, the preview, adoption, the option matrix and the
D5/D6/D8/D13/D14 copy are unchanged; only the D3 sentence's render site gained the list. Two
carried comment fixes land with it: the review's abandonment note now calls the retained
preview slot the intentional rule (ADR 0049's 2026-11-18 amendment, ENG-1) instead of a
"recorded deviation", and `edit/op-summary.ts` no longer claims no web surface authors
`column-repair` ops (false since EW-04I).

**Tests.** `csv/header-renames.test.ts` pins the whole evidence table, every bail-out, the
bounded read (the slice bound itself is asserted) and the dialect decoding;
`csv/CsvReviewDialog.test.tsx` pins the verified list for `dup-header.csv`, the
quoted-delimiter/quoted-newline record, the "renamed nothing" sentence, every fallback, the
pending state, and a no-console/no-`data-*` privacy assertion; `tests/e2e/csv-preview.spec.ts`
adds the two real-engine legs — the list before adoption (and the adopted grid headers
matching it) and the quoted-newline fixture producing no false list.
