feat(p2-5): `assay pipeline` now executes the full P2 semantics — validation/diff/publish gates, per-node materialization, and gate-failure exit classes — and `pipeline validate` gains a static gate-visibility view.

**`run`** drives the p2-4 runner with the parsed contracts and explicit diff keys, and reports every node's materialization plus value-free gate verdicts. `validate` nodes run the existing M5 machinery (a failing verdict is a first-class `gated` result, not a crash); `diff` nodes run the M6 row-diff machinery and surface added/removed/changed counts (never values); `publish` nodes are gate evaluation and a blocked publish is a `gated` result naming its missing gates; `view`/`ephemeral`/`table` materialization is reported per node. A gate failure is a RESULT: exit 1 with the report on stdout, distinct from engine failure. An `export`/`publish` materialization mode this surface cannot execute is a typed mode refusal (`status:'refused'`, exit 1), never an "internal error"; `publish`-mode and `cache`/`incremental` modes remain compile refusals. Exit mapping is unchanged where p-4 settled it: `0` completed/would-run; `1` DAG-or-compile refusals, typed node failures, gate failures, and mode refusals (all results); `2` malformed input, unreadable files, bad usage, and unresolvable sources/contracts. This also fixes the p2-4 carry-over that rendered a user-authored export/publish-mode plan as an internal error.

**Checkpoint C2.** Every `validate` node's `contract` reference resolves relative to the PIPELINE FILE's directory (absolute paths pass through), is read, and is parsed with the m5-0 total parser. All missing/unparseable failures are collected in node order, disclosed value-free and node-attributed, and refused before any engine call (exit 2) — never guessed or inferred. `diff` nodes have no keys in the IR, so the CLI accepts an explicit repeatable `--key <column>` set (applied to every diff node); a diff node with no key set is a disclosed would-fail at `validate` and an exit-2 refusal at `run`. `--infer`-shaped guessing stays rejected.

**`validate` gate-visibility (no execution).** The report lists every node with its effective ADR 0033 materialization mode and a `gates` section showing each validate/diff/publish node's input/against, authored contract reference with its C2 resolution status (resolved/missing/unparseable), publish `requires` edges, and a static `bound` verdict; unbound bindings are disclosed as `gateErrors` and make the report invalid (exit 1). The validate path still never loads the native engine and never opens a dataset.

**Versioned envelope shape change** (the `report` marker is unchanged; `reportVersion` follows the p-4 discipline — this is a minor release): the `assay-pipeline-validate-report` envelope gains per-node `materialization` plus `gates[]` and `gateErrors[]`; the `assay-pipeline-run-report` envelope gains per-node `materialization` and `gate`, a `status` union extended with `gated` and `refused`, and the `gatedAt`/`gate`/`refusal`/`refusalNode` fields. Machine-local paths (including export destinations) are never emitted; every pipeline-derived string is sanitized at the rendering boundary.

New golden fixtures `fixtures/pipeline/cli_gated.yaml` (a contract requiring more rows than the filtered relation has) and `cli_gated_pass.yaml` (the passing variant) with their contracts back a gated-then-passing real-engine journey, plus the byte-pinned envelopes for every new outcome. No telemetry; no engine changes.
