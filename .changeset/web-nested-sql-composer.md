feat(m3-4): nested SQL composition — a pure, Node-tested composer (`apps/web/src/sql/nested-compose.ts`) for the three nested operations that m3-5 will wire into the schema-tree/header click paths and the m2-4 SQL result pane. **Flatten** turns a STRUCT column into quoted dotted child columns (`"meta"."src" AS "meta.src"`, honest errors for non-struct/empty/degenerate inputs instead of a silent `SELECT *`). **Explode** turns a LIST column into rows via FROM-clause `UNNEST(…) WITH ORDINALITY` (CLI-verified on DuckDB 1.5.5): other columns kept view-qualified, element column keeps the list name, 1-based position column `"<list>.pos"`, NULL lists yield one NULL row while empty lists yield zero rows, NULL elements preserved, list-of-struct fields reachable through the element alias, fixed-size arrays rejected with an evidence-backed error. **Path extraction** composes bracket paths with app-side 0-based indices converted to DuckDB's 1-based indexing, field names escaped as `''`-doubled single-quoted literals (backslash is not an escape in DuckDB — verified), and aliases mirroring the emitted path. Every identifier passes the engine's `quotedIdentifier` (now exported from `@assay/engine-duckdb` — additive, m2-7 fold precedent), so hostile names (`weird "quoted" key`, embedded `;`/`--`/quotes/brackets/unicode) stay inside identifier/literal context; all composed SQL is pinned byte-exactly with recorded CLI executions.
