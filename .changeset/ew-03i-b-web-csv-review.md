feat(ew-03i-b): add the web CSV review surface — a non-adopting preview (options, sniff disclosure, bounded sample) that a user can then adopt (EW-03I web half; ADR 0049 decisions 4/6/7, its acceptance resolutions, and the EW-03D ledger accepted as a block).

**Entry points, with quick open untouched.** A second, explicit control — `Review CSV options…` — sits beside the Open control in the idle open surface and in the ready-state replacement gesture (EW-03D §3). The ordinary Open path is unchanged, including at the call site: with no reviewed options it still calls `engineClient.open(source)` with a single argument, so no `options` field is ever composed (pinned by RTL and by an e2e wire observation). A non-`.csv` pick from either review control falls through to today's path with no new copy and no review.

**The review is non-adopting.** `apps/web/src/csv/` adds a native `<dialog>` (the guide/guard idiom: UA top layer, UA focus scope, Escape = Stop reviewing) that only ever calls `engineClient.csvPreview`. It never opens, never writes a session table, never sets a phase and never touches a `TableRegistry`; `previewId` is display bookkeeping (no protocol op accepts it). In a ready session it occupies the existing WF-06 `choosing` intent, so the shell stays owned, the gate/busy/editor/cast refusals and the dirty guard behave exactly as they do for any other replacement gesture (`desiredModeRef` only remembers which picker path the gesture chose, across T5/C11).

**Options compose through the engine vocabulary, not a copy of it.** The form (delimiter, header, all-text, inference sample size, NULL string, date format, quote, escape, comment prefix, rows to skip, per-column `name: TYPE` lines) builds a plain record and hands it to `@assay/engine-duckdb`'s `parseCsvOptions(input, 'preview')`; the typed, value-free reason is surfaced verbatim and a refused set is never dispatched. Unknown/deferred/always-refused keys are unreachable from the form. Adoption parses the same reviewed set as `'open'` with `sample_size` removed — the preview-only inference input never rides `engine/open` (ADR 0049 item 1).

**Honest sample and disclosure.** The sample cap is a stated constant (50 rows, ≤ `MAX_RANGE_ROWS`) and the UI states the cap the RESPONSE applied (`rowCap`), respects `hasMore`, renders NULL as `NULL` (never a blank), formats cells through the grid's own `formatCell`, projects rows through the existing `projectBatchToRows`, and withholds the sample with a fixed sentence if the batch and the engine's column disclosure disagree. The sniff disclosure renders delimiter/quote/escape/newline/comment/skip/header/per-column types/dateformat/timestampformat and the `Prompt` as display text; the effective option set is disclosed separately. Copy is authored in-row against the accepted ledger (D3 rename behaviour, D5 no locale inference, D6 empty/quoted-empty both NULL by default, D13/D8 no silent row-skip and "a sample is not an evaluation of the whole file", D14 unsafe integers with the type/all-text escape offered and nothing forced) and pinned by literal RTL assertions **plus a negative assertion that the surface never renders "validated/checked/verified/confirmed"** around a successful sample. Adoption is disabled whenever the form, a refusal, an in-flight read or a failed read means the sample on screen is not the set that would be opened, and the surface then says the sample is stale.

**Failure surface.** Preview failures use `engineErrorMessage('csv-preview', error)` — the engine's honest first line with an operation framing (`The preview could not be read: … Nothing was opened.`) where the bundle carries one, and the existing value-free fallback where it does not (opaque glue text is never classified, ADR 0048/EW-03D D10). No dataset value, filename or path is rendered, logged, put in a `data-*` attribute or attached to telemetry; the picked name stays hidden (ADR 0025). No telemetry event, field or route is added.

**Adoption is exactly once, through the existing guards.** Idle adoption hands the reviewed file + option set to the ONE open chain through a one-shot ref (the idle-example/drop precedent), which then runs the ordinary guarded `engine/open` carrying the reviewed options. Ready adoption goes through the existing `prepareReplacementCandidate` → `adoptReplacementCandidate` pair (`canAdopt` unchanged): a fresh `engine/open` with the reviewed set (ADR 0049 acceptance resolution 5 — never a promotion, never a second `TableRegistry` writer), one new session, one `dataset_opened`.

**Abandonment, and a recorded divergence from ADR 0049 decision 4.** Stop (or Escape) drops the local candidate, bumps the intent sequence so every late preview result is discarded, ends the intent, and says "You stopped reviewing. Nothing was opened." — never "aborted", and never that a preview slot was released. **Known limitation, disclosed rather than papered over:** ADR 0049 decision 4 says the preview slot drops its view and file "on abandonment", but the merged engine has no host-reachable release op (`releasePreviewSlot()` runs only on the next preview, an `engine/open`, or `engine/dispose`). After an abandoned review **one** staged preview (registered file, no view, no `TableRegistry` entry) is therefore retained until the next preview, the next open, or `engine/dispose` — bounded by the single slot, consistent with ADR 0047, and priced by ADR 0049's own retention table ("failure after the slot registered: +1 until the next slot event or dispose"). No engine op, protocol field or fake call was added to force a release; that is a candidate engine row, not a web-side workaround.

**Tests.** `apps/web/src/csv/{options,preview}.test.ts` pin the option matrix and the projection; `csv/CsvReviewDialog.test.tsx` pins every user-visible sentence as an independent literal, the prohibited-wording negative assertion, the cap-from-response behaviour, the adopt-exactly-once contract (including that the adopted set never carries `sample_size`), staleness blocking, both failure paths, out-of-order/late-result dropping (also after abandonment) and the privacy negatives; `App.csv-review.test.tsx` drives the real composition root for both entry points, the byte-identical quick open, the ready-session WF-06 path and abandonment; `tests/e2e/csv-preview.spec.ts` is the real-engine journey on the golden `semicolon.csv`/`customers.csv` fixtures (disclosure follows a delimiter override, adoption carries it on the wire, stop opens nothing, quick open sends no options field, ready-session replacement, and a refused option never reaching the engine). One narrow addition to `edit/session.ts` adds the `csv-preview` operation framing and its test.
