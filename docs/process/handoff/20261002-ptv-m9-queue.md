## 2. Ordering, parallelism & conflict rules

1. **ptv-1 first** (the D15 headline; e2e-independent but research-heavy). **m9-1 second**
   (solo docs; zero file overlap with ptv-1 — different `docs/` subtrees and `apps/vscode`).
2. One dispatch at a time (serialized, per the operating model); no worktree parallelism needed
   for two rows with disjoint paths.
3. **STOP boundaries:** ptv-1 — any production extension feature beyond the repro scaffold, or a
   repro that requires uncommitted secrets/services, stops and reports. m9-1 — any question
   ADR 0014 doesn't settle goes to the D17 open-questions list, never decided in-task.

## 3. Standing notes (invariants every task respects)

- **D15 discipline:** the spike does not commit PT-V. Its recommendation is evidence, and the
  track-start ruling reads it — do not begin "PT-V slice 1" work in ptv-1.
- **D16 discipline:** the spec does not decide the format. Proposed ADR 0046 stays Proposed;
  the P3 queue is authored only after D17.
- **ADR/decision hygiene:** no accepted ADR is touched; new durable decisions come back as
  rulings, never silent.
- **Privacy:** value-free everywhere; the spike handles local fixtures only; no telemetry
  (nothing new; `pipeline_run` stays reserved).
- **Verification:** every row runs `format:check / lint / typecheck / test / test:coverage /
build / docs:links:check`. **ptv-1:** playwright e2e not required (no shared web/e2e surface —
  reviewer verifies via diff-stat and re-runs the spike harness instead). **m9-1:** docs-only,
  all seven doc gates.
- Workers never touch `docs/**` except ptv-1's single pre-authorized deliverable file; one
  Conventional Commit + changeset per row (m9-1 excepted, docs-only); tree clean after.
