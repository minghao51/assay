## 2. Ordering, parallelism & conflict rules

1. **The table order is the dispatch lane** (p3-1 pure core → p3-2 candidate reference → p3-1b disclosure → p3-3 CLI → p3-4 web →
   p3-5 conformance). One worker per row; worker → independent reviewer per
   [operating-model §7.1–7.3](operating-model.md); serialized subagent dispatches.
2. **Serialization rule (identical in both queues):** the two queues share the
   `packages/engine-duckdb` surface (P3's runner work; PT-V's client/worker seam) — per
   [operating-model §7.4](operating-model.md) they run on **ONE serialized dispatch lane**: one
   queue at a time, one row at a time. Default order: **P3 first** (the D17 chain), PT-V slice 1
   second; the orchestrator may interleave a PT-V row touching only `apps/vscode/**` if P3's
   in-flight row does not touch `engine-duckdb`. No worktree parallelism unless the orchestrator
   explicitly splits lanes.
3. **STOP boundaries:** any publish-mode wiring (ADR 0033/0035 — the boundary stays explicit);
   any non-additive format change (D17-Q12 — additive-only within v1 is a ruling constraint; a
   perceived need = STOP and report); any hosted-concern field (comments/approvals/policy —
   ADR 0014's M10/G3 concerns); any boundary crossing outside the row's scope column.

## 3. Standing notes (invariants every task respects)

- **D17/[ADR 0046](../../adr/0046-dcr-artifact-format-v1.md) discipline:** the format is FIXED —
  additive-only within v1 (D17-Q12); a version bump is a maintainer-visible decision. Do not
  re-derive what the ruling settled — the [spec §9](../../product/06-dcr-artifact.md) carries each
  outcome.
- **Privacy ([ADR 0025](../../adr/0025-telemetry-and-data-privacy-boundary.md)):** value-free
  everywhere — no dataset contents, raw SQL results, or sensitive paths — including fixtures and
  the committed golden artifacts.
- **Purity/dependency discipline:** `domain` stays dependency-free; `pipeline` free of
  dbt/SQLMesh/Dagster runtimes (ADR 0031/0032); packages never import apps.
- Dataset-shape bug fixes ship a minimal golden fixture + regression test (AGENTS.md).
- One Conventional Commit + changeset per row; workers never touch `docs/**` (the orchestrator
  owns paperwork); tree clean after.
- **Gates per row:** the seven — `format:check / lint / typecheck / test / test:coverage / build /
docs:links:check`; e2e where web-visible (p3-4).
