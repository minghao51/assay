## 2. Ordering, parallelism & conflict rules

1. **p2-1 → p2-2 → p2-3 → p2-4 strictly serialized** (each consumes the previous; p2-1 first
   because it re-homes shared files p2-5/p2-6 would otherwise conflict on).
2. **p2-5 ∥ p2-6** after p2-4 (disjoint surfaces: CLI vs web). p2-6 additionally requires p2-1's
   view-as-handle op.
3. **p2-6 vs q-15 (shell slice 2):** both touch web section layout — serialize or coordinate;
   land whichever claims first, rebase the other (same rule PT-P used for p-5 vs ux-6).
4. Engine changes stay **additive-only** (D13: `packages/engine` is a documented target, not a
   dependency); every engine task rides the conformance suite.

## 3. Standing notes (invariants every task respects)

- **ADR boundaries:** 0029 SQL-first; 0030 owned IR (no adapter-native formats); 0031 no
  dbt/SQLMesh/Dagster runtime deps (lint-enforced — p2-1 closes the `@dagster-io/*` gap); 0032
  **no orchestration ever** (no scheduling/retries/sensors/run state — a run is one explicit
  execution); 0033 materialization is logical + backend-mapped, **unsupported modes fail
  explicitly** (no silent semantic changes); 0034 ingestion stays separate; 0035 gates are
  first-class pipeline semantics (visible in the flow, not side reports).
- **Purity zones:** `packages/pipeline` model/compile code stays dependency-free and pure
  (`yaml` + `@assay/validation` + `@assay/contracts` only, per the landed precedent); the runner
  lives in `engine-duckdb` importing `@assay/pipeline` (direction-legal one way only).
- **Format discipline:** canonical one-shape-per-meaning serialization, byte-stable; total
  located-error parsers (never throws); exact-or-rejected numbers; reserved `assay_*` namespace;
  **v1 stays additive** — any non-additive IR change is a STOP-and-report (version bump =
  maintainer-visible decision).
- **Error discipline:** value-free, node-attributed failures; sanitizer at every rendering
  surface (one shared home after p2-1); C2 never-guess (disclose or refuse) for all file/contract
  resolution.
- **Telemetry:** `pipeline_run` remains reserved/rejected (design §3 + ADR 0045) — activating it
  is a maintainer decision, not a rider. No new events in this queue.
- **STOP-and-report boundaries:** IR version semantics; gate-threshold semantics beyond ADR
  0035's list; publish-mode materialization (P3/DCR); the ephemeral local mapping if contested;
  anything that would break an accepted ADR. Boundary questions go to the orchestrator, not
  re-decided in-task.
- **Verification:** every row runs the full gate set (`format:check / lint / typecheck / test /
test:coverage / build / docs:links:check`, plus `test:e2e` with `DUCKDB=/tmp/duckdb` when
  web/e2e surfaces change — workers on shifted ports 4273/4279/4280); reviewers re-run gates and
  drill mutation holes; baseline counts are cited per claim. The known DuckDB-CLI flake in
  `engine-duckdb/src/row-diff-agreement.test.ts` (observed once under load, 2026-09-30) is
  watched, not blocked on — re-run in isolation and note it.
- Workers never touch `docs/**` (orchestrator owns this file and the handoff); one Conventional
  Commit + changeset per row; tree clean after.
