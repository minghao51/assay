## 2. Ordering, parallelism & conflict rules

1. **ux-1 first** — the only outright defect (P1); everything else is polish/planning. Small,
   isolated (grid + fixture), gate-clean.
2. **ux-2 → ux-3 serialized** (both re-render `App.tsx`'s shell region). ux-3 may then run
   parallel to ux-4 (disjoint files: profile/diff/edit/grid vs FilterBar+builder).
3. **ux-4** touches `FilterBar.tsx` only (plus a new pure module) — parallel-safe against ux-3,
   but serialize against ux-1's landing if the e2e wide-fixture spec touches shared helpers.
4. **ux-5 is docs-only and parallel-safe from day one** — dispatch it alongside ux-1 if capacity
   allows (different executors, disjoint paths).
5. **ux-6 blocked**: requires the ux-5 ruling AND ux-1 landed. Do not start early.
6. **ux-7** anytime, solo/batchable.

## 3. Standing notes (decisions and invariants these tasks must respect)

- **Privacy (ADR 0025):** no filenames in any new copy; status lines stay value-free. The
  "Dataset · N rows" rewording must not reintroduce the file name.
- **Byte-stability:** web display formatting (ux-3) must not touch the diff/validation report
  export envelopes or CLI output — display-only layer.
- **Engine contracts:** ux-4 compiles to the existing `FilterSpec` grammar; no engine or
  `GridViewportModel` protocol change. ux-1 is CSS/DOM-structure only (no fetch/window changes).
- **Test pins:** `open-status` text is pinned by many specs — migrate pins through
  `tests/e2e/support/fixtures.ts` first (q-5 consolidation means most go through it), then sweep
  the remaining direct pins. Keep the shared helper the single authority.
- **ADR rule:** ux-5 files a Proposed ADR only if the shell direction is durable architecture;
  otherwise the product note + roadmap row suffice. Never re-decide accepted ADRs (0022 grid
  rendering replaceability is adjacent — cite it in the spec).
- **Accessibility floor:** every task keeps the dual-scheme axe gates green with an empty
  allowlist; ux-2/ux-6 add focus/announcement behavior that q-3/au3-8 established patterns for
  (modal focus trap, roving tabindex) — reuse, don't reinvent.
- **No telemetry** is added by any task (nothing here needs it; ADR 0037 disclosure would apply
  otherwise).
