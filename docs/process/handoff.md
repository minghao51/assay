## 1. Project identity

**Assay** — _the local-first data workbench_: inspect, validate, compare, repair, transform, and govern structured datasets (Parquet, JSONL, JSON, CSV, Arrow/Feather) in the browser or VS Code, with data never leaving the user's machine by default. Long-term direction: governed data products and an enterprise data control plane.

- **Positioning:** "Understand any dataset before your code does."
- **Stack:** TypeScript · React/Vite · DuckDB-WASM · Apache Arrow · pnpm/Turborepo monorepo.
- **License:** AGPL-3.0-or-later for the open core (ADR 0036).
- **Phase:** post-MVP launch readiness (PT-0 → gate G0). **MVP feature milestones M0–M6 complete** (M6 closed 2026-09-21 — exit journey green, exact web≡CLI diff agreement); per maintainer decision D11 (2026-09-21) the VS Code surface (former M7) moved to the **post-MVP track** — see `../product/04-post-mvp-track.md` (PT-0 launch readiness to G0, PT-V VS Code, PT-P pipeline, PT-H hardening; D12 open: which engineering track first).

## 4. Environment & tooling (including discovered quirks)

- **Node 24** via nvm; repo pins `.node-version`. **pnpm 11.26.0** comes from corepack via the `packageManager` field — if `pnpm` is not on PATH, prefix commands with `corepack` (e.g., `corepack pnpm install`).
- **pnpm 11 quirks:** build scripts are blocked by default — `allowBuilds: { esbuild: true }` in `pnpm-workspace.yaml` already handles it. After renaming package scopes, always re-run `pnpm install` so workspace links refresh.
- **DuckDB CLI** (v1.5.5 used) regenerates Parquet fixtures: `bash fixtures/parquet/generate.sh` (or `DUCKDB=/path/to/duckdb …`). DuckDB 1.5.x rejects the new lambda syntax — the generator avoids lambdas entirely.
- **Playwright browsers:** `pnpm exec playwright install chromium` once; CI installs its own.
- **No services, no secrets** — local-first; nothing to configure beyond the above.
- **Missing infra (deliberate, tracked):** git hosting done 2026-09-21 (remote, CI, SHA-pinned actions — see [manual-actions](manual-actions.md) M2/M3; org transfer + public flip remain maintainer calls); benchmark harness (O2) landed and hardened (m1-7/T4); a11y CI (O3) **landed with pt0-4** (dual-scheme axe-core e2e scans, empty deferred-findings allowlist + non-vacuity canary — see §2 Tests); demo dataset (O5) approach decided (hybrid), curation not started.

- **Local-e2e jitter (2026-09-21, observed):** the full e2e suite on this machine intermittently
  drops 15–20 random tests per run (uniform signature: `open-status` stuck at "opening" past the
  5 s default `toHaveText` timeout; one run aborted a worker mid-suite), while the same suite is
  green in remote CI ×3 on the same lineage and green locally in isolation / intermittently
  full-suite. Healthy opens measure 1.8–2.3 s (traced). Host suspects (not repo defects):
  sporadic I/O bursts (qbittorrent-nox lifetime writes ≈ 230 GB on the same NVMe), NoMachine
  streaming, ES-CPU quirks; 57-day uptime. Not CPU throttling (boosts 3.8 GHz), not disk (18 %
  used), not RAM (22 GiB available), not stale builds/fixtures. **Mitigation:** pt0-0 gives every
  open-ready wait an explicit generous timeout; for bench-grade runs pause torrenting/remote
  streaming. Baseline pins below cite CI for e2e when local is jittery.

## 5. Definition of done — every change

1. `pnpm lint && pnpm typecheck && pnpm test && pnpm build` green (CI enforces; e2e for web-visible changes).
2. Package changes include a changeset (`pnpm changeset`); product-level narrative changes update root `CHANGELOG.md`.
3. Durable decisions get an ADR (`docs/adr/template.md`, next free number — currently 0046) and a roadmap-backlog update.
4. Dataset-shape bug fixes ship a minimal golden fixture + regression test.
5. Privacy/security rules respected (ADR 0025/0007; see AGENTS.md "Hard rules").
