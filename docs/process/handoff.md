## 1. Project identity

**Data Workbench** — a local-first dataset workbench: inspect, validate, compare, repair, transform, and govern structured datasets (Parquet, JSONL, JSON, CSV, Arrow/Feather) in the browser or VS Code, with data never leaving the user's machine by default. Long-term direction: governed data products and an enterprise data control plane.

- **Positioning:** "Understand any dataset before your code does."
- **Stack:** TypeScript · React/Vite · DuckDB-WASM · Apache Arrow · pnpm/Turborepo monorepo.
- **License:** AGPL-3.0-or-later for the open core (ADR 0036); hosted/enterprise surfaces may be separately licensed.
- **Phase:** pre-MVP. Milestone **M0 (bootstrap) complete**; **M1 (local file explorer) is next**.

## 4. Environment & tooling (including discovered quirks)

- **Node 24** via nvm; repo pins `.node-version`. **pnpm 11.26.0** is provided by corepack automatically from the `packageManager` field (if `pnpm` is missing, `corepack enable` or prefix commands with `corepack`).
- **pnpm 11 quirks:** build scripts are blocked by default — `allowBuilds: { esbuild: true }` in `pnpm-workspace.yaml` handles it; pnpm also auto-verifies lockfile supply-chain state.
- **DuckDB CLI** (v1.5.5 used) is needed to regenerate Parquet fixtures: `bash fixtures/parquet/generate.sh` (or `DUCKDB=/path/to/duckdb …`). DuckDB 1.5.x rejects the new lambda syntax — generator SQL avoids lambdas entirely.
- **Playwright browsers:** `pnpm exec playwright install chromium` once; CI installs its own.
- **No services, no secrets** — the product is local-first; nothing to configure beyond the above.
- **Missing infra (deliberate, tracked):** git remote/hosting not yet chosen; CI therefore never run remotely; benchmark harness (opportunity O2) and a11y CI (O3) not yet wired; demo dataset curation (O5) not started.

## 5. Definition of done — every change

1. `pnpm lint && pnpm typecheck && pnpm test && pnpm build` green (CI enforces).
2. Package changes include a changeset (`pnpm changeset`); product-level narrative changes update root `CHANGELOG.md`.
3. Durable decisions get an ADR (template: `docs/adr/template.md`, next free number) and a roadmap-backlog update.
4. Dataset-shape bug fixes ship a minimal golden fixture + regression test.
5. Privacy/security rules respected (ADR 0025/0007; see AGENTS.md "Hard rules").

## 7. Operating model

- **Sequencing:** capacity-based (D5); quarterly roadmap review; immediate update on gate passage.
- **Gates G0–G4** control hosted/enterprise investment — never start gated work without the gate passing (see roadmap §5).
- **Decisions:** roadmap backlog §7 is the ledger; ADRs are the durable records; docs yield to ADRs on conflict (update doc in same PR).
- **Changes:** Conventional Commits; changesets for packages; product changelog for narrative.
- **AI agents:** follow `AGENTS.md` (hard rules incl. dependency direction, privacy, license compatibility).
