## 1. Critical (fix immediately — AR-1/AR-2)

### AR-E1 — CSV formula-injection guard bypassed via `BLOB` columns `[REPRO]`

- **Where:** `packages/engine-duckdb/src/overlay-query.ts:498,549` (guard predicate) +
  `packages/engine-duckdb/src/type-expr.ts:137-146` (`STRING_FAMILY_BASES` — no BLOB family).
- **Defect:** the export sanitizer fires only for the string family (`VARCHAR/TEXT/STRING/CHAR/
CHARACTER/BPCHAR/NVARCHAR/ENUM`). DuckDB's CSV writer emits `BLOB` bytes **raw** — reproduced on
  the pinned CLI: `COPY (SELECT '=cmd|@SUM(1+1)'::BLOB AS b) TO … (FORMAT CSV)` writes a live
  formula-leading cell. Reachable from any Parquet `BYTE_ARRAY` column inferred as `BLOB`
  (overlay-free base export takes the DESCRIBE type verbatim) and from a `column-cast → BLOB`
  overlay (`overlay-wire.ts` accepts BLOB). Violates the AGENTS hard rule and the SECURITY.md
  probeable invariant ("formula-injection-safe CSV export").
- **Coverage gap:** the conformance suite has zero BLOB CSV-export coverage (BLOB appears only in
  a cast-check dataset, never exported).
- **Fix direction:** classify `BLOB/BYTEA/BINARY/VARINARY` as formula-capable and guard via a text
  rendering (cast to `VARCHAR` — e.g. `encode()`/hex policy, worker's choice documented — before
  the guard), or hex-encode BLOBs on CSV export; add a conformance `export-round-trip`-style
  scenario with a BLOB bait cell + e2e pin. **Owner: AR-1.**

### AR-W1 — Web cell editor survives an epoch shift → wrong-row commit `[REPRO]` (structural)

- **Where:** `apps/web/src/grid/DataGrid.tsx:129` (`editing` holds `rowIndex/columnIndex`
  positions only), `:222-227` (invalid draft → `setEditError` + return — editor stays open),
  `:159-163,196-203` (`commitEditValue` resolves the logical `rowId` **at commit time** from the
  position), and no `useEffect` invalidates `editing` on model/epoch change (only 2 effects exist,
  neither touches `editing`).
- **Defect:** edit a cell → type an invalid draft → blur via a sort/filter click (validation
  rejects, editor persists; the click re-sorts/filters → `refresh()` → new epoch, rows
  renumbered) → correct the draft → Enter ⇒ the value commits against **whatever row now sits at
  the stale position**. A wrong-row write and a stale-editor-as-truth violation.
- **Fix direction:** key the editor by the logical `rowKey` captured at `beginEdit`, or invalidate
  (`setEditing(null)` + readable reason) on any model version/epoch bump; pin with an e2e drill
  (edit → reject → sort → commit must not land on the shifted row). **Owner: AR-2.**

No other critical findings. Notably: **no XSS surface** (zero `dangerouslySetInnerHTML`/`.innerHTML`;
all dataset content renders as React text), **no telemetry/network code**, prod `pnpm audit` clean,
and the engine's core boundaries (quoting helpers, type-expression validation, plan wire gates,
`BEGIN…ROLLBACK` containment) held against every hostile probe in every lane.
